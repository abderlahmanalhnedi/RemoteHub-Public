## Documentation principles

- Describe current source behavior without implying certification or a
  production-readiness guarantee.
- Distinguish implemented behavior, automated tests, and live protocol
  verification.
- Use repository-relative links.
- Keep credentials, private infrastructure, customer data, local paths, and
  unreviewed screenshots out of documentation.
- Update limitations and security boundaries when the implementation changes.
